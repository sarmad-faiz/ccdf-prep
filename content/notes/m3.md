Core idea: what works on your machine must hold for teammates, in production and under security review. Control what agents may do, give them durable instructions, package reusable integrations.

## Permission modes
- **Explore → plan → code**: Claude reads and traces, proposes a plan, writes only after approval. **Plan mode** blocks all edits and shell commands until released; default for unfamiliar or high-stakes code.

| Mode | Behaviour |
|---|---|
| `default` | Auto-approves reads; prompts before nearly every edit/command |
| `acceptEdits` | Auto-approves edits **and common file commands, including `rm` in the working dir** |
| `plan` | Read-only exploration |
| `auto` | **Classifier-gated**: fewer prompts, keeps a safety net |
| `dontAsk` | Listed mode |
| `bypassPermissions` | No prompts at all **and skips the protected-path guard** |

| Settings level | File | Applies to |
|---|---|---|
| User | `~/.claude/settings.json` | All your projects |
| Project | `.claude/settings.json` (committed) | Everyone who clones |
| Local project | `.claude/settings.local.json` (auto git-ignored) | You, this project |
| Enterprise | `managed-settings.json` | Whole org; **can't be overridden** |

- Allow/ask/deny rules sit on top of the mode. **Deny always wins.** Strongest control = **enterprise deny rule** (holds even under bypass).
- Choose mode by **risk and reversibility**, not speed. Fewer prompts safely → `auto`, not bypass.
- **Human gate**: ask *worst outcome if this runs unchecked?* Reversible → no gate. Hard to undo or sensitive path → deny rule or keep the prompt. Team-marked sensitive code → human review before merge, always.
- Deny-rule sensitive dirs **before** switching to a looser mode. Permission prompts don't replace deny rules or hooks.
- **AI code review = findings to triage.** Trust diff-provable findings; runtime claims are hypotheses; give the reviewer your conventions.

## Project context
- **`CLAUDE.md`**: loaded in full at every session start. `/init` generates a starter; refine it (test commands, conventions, no-touch paths).
- **Size is the failure mode**: more lines dilute each rule. Keep behaviour-changing rules only; move procedures to Skills; must-never-break rules → **a hook**.
- **Rules files** (`.claude/rules/`): scoped by a **`paths` glob in frontmatter**. Folder placement doesn't scope; **no `paths` → loads at start like `CLAUDE.md`**.
- Universal rule → `CLAUDE.md`. Path-specific rule → rules file.

**Hooks**: your script on a lifecycle event; runs every time, regardless of the model or permission mode. Event + optional matcher + command, set in settings or `/hooks`.

| Hook | Fires | Use |
|---|---|---|
| `PreToolUse` | Before a tool call | **Can block**: exit code **2**, reason on **stderr** |
| `PostToolUse` | After a tool call | **Can't block**; format, test, **audit log** |
| `UserPromptSubmit` | Prompt submitted | Inject context, validate |
| `Stop` | Response finished | Notify, clean up |
| `Notification` | Needs permission or idle 60 s | Route alerts |
| `SessionStart` / `SessionEnd` | Start or resume / end | Set up env / final audit |

- **Instruction = "most of the time"; hook = every time.**
- **Subagents** start with a clean context: no main history, no files, no skills; they return only output.
- Built-in **Explore and Plan skip `CLAUDE.md` and git status**; general-purpose loads both. Custom subagents (`.claude/agents`) must list skills in frontmatter.

| Mechanism | Loads | Use for |
|---|---|---|
| `CLAUDE.md` | Every session | Universal rules, commands |
| Rules file | On matching `paths` | Path-specific guidance |
| Hook | Runs a script | Guardrails, side effects, audit |
| Subagent | Only its task | Exploration, bloat-prone or parallel work |

## Packaging workflows
- **Skill** = `SKILL.md` in `.claude/skills`; frontmatter (name, **description = when it applies**) + steps. Loads on description match or `/skill-name`.

| Runtime | How skills load |
|---|---|
| Claude Code | From `.claude/skills`; runs locally under permission mode + deny rules |
| Messages API | Beta headers; runs in the **code execution container** (no local files) |
| Agent SDK | Set **`settingSources`** explicitly |
| Managed Agents | Listed on the agent resource; `managed-agents-2026-04-01` header |

- **Portability rules**: specific description; no local path/tool assumptions; **subagents don't inherit skills**.
- **Commands**: skills are now the command format (`/skill-name`); `.claude/commands/` is **legacy**. `disable-model-invocation: true` → runs only when called explicitly.
- **Plugin** = versioned bundle of skills, hooks, subagents, MCP servers. Commands are namespaced: `/payments:run-tests`.
- **Marketplace** = plugin catalog. Add one with `/plugin marketplace add owner/repo`. Enterprise: managed **allowlist restricts but doesn't register** → add `extraKnownMarketplaces`.

| Layer | Use when |
|---|---|
| Skill | A procedure that should stay out of context until needed |
| Command | A named procedure you trigger explicitly |
| Plugin | Setup must be shared, versioned and consistent across a team |

- A plugin carries **only what it bundles**; your local deny rules don't travel.
- **Install ≠ run**: absolute or `~` paths and undocumented env vars install fine, then fail. Use **`$CLAUDE_PROJECT_DIR`** / **`${CLAUDE_PLUGIN_ROOT}`**, document env vars, test on a clean machine.

## MCP servers
- MCP server exposes:
  - **Tools**: actions the model calls.
  - **Resources**: read-only data the **client** fetches by address (direct or templated); client support varies.
  - **Prompts**: vetted templates invoked by name.

| Transport | Use |
|---|---|
| `stdio` | Local subprocess; personal tools. **Not for sharing** |
| HTTP | Remote or shared by a team (e.g. GitHub MCP) |

| Scope | Stored in | Shared |
|---|---|---|
| Local | `~/.claude.json` (per project path) | No |
| User | Personal settings | No; all your projects |
| Project | `.mcp.json` at repo root (committed) | Everyone who clones |
| Enterprise | Admin-managed config | Whole org |

- Match transport to where the server runs, **then** choose scope. A project-scoped stdio server makes each teammate run it (needs the runtime).
- Claude Code **defers** tool definitions and loads them via search by default.
- **Per-tool rules**: `mcp__server__tool`; a deny on one tool beats an allow on the server. In the API, `enabled` = whether the model **sees** a tool; permission rules = whether it may **run**.
- **Auth**: GitHub = PAT as `Bearer ${TOKEN}` from an env var; Linear = **OAuth** browser sign-in. Never inline keys in `.mcp.json`; a committed key stays in history → **rotate**.
- Enforce with `CLAUDE.md` convention **plus** a `PreToolUse` hook that blocks inline credentials.
- Skip MCP for one-off, single-person tasks.

**Prompt caching:**
- `cache_control` `ephemeral` on the last block to cache; **no global switch** in this model; up to **4 breakpoints**; order **tools → system → messages**.
- TTL **5 min from last read** (each hit resets); optional `ttl: 1h` for long gaps. Minimum ~**1,024 tokens**.
- One changed character before the breakpoint → cache miss. Caching saves processing, not context space.

**RAG**: keep material outside context and fetch the relevant slice. Classical RAG = chunks + embeddings indexed upfront; agentic search = search live. Only as good as what it retrieves.

## Enterprise integration
Production asks: **who is the model acting as? what data leaves, to where? can admins lock config? is access logged?**

| Service | Auth | Secret lives | Lock |
|---|---|---|---|
| Remote, user identity (SaaS) | **OAuth** (401 → browser sign-in) | Token stored by client | Enterprise managed settings |
| Remote, service identity | **API key in env var** | Environment only | Enterprise managed settings |
| Local (files, local DB) | **File-system permissions** | No credential; deny rules | Managed deny rules |

All three: `PostToolUse` **audit hook**.

**Secrets:**
1. **Separation**: config holds a variable reference only.
2. **Home**: env var (local, short-lived) or **secret store** (shared, audited, one rotation updates all).
3. **Rotation**: on schedule and **immediately on exposure**; the only fix for a leak.

- Regulated add-ons: config lock → managed settings; logging → `PostToolUse` hook; **residency** → regional endpoint + platform pinning.
- **Code modernization**: plan mode for review, hooks on sensitive paths, `CLAUDE.md` holds target patterns. Ask: blast radius? how audited? who approves each phase?
- **OAuth redirect URIs are per host**: staging working ≠ prod authorized. Regulated customers often need separate OAuth apps per environment.
