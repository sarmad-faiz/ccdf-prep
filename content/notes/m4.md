Core idea: development hides what production reveals. Most failures are **a decision never made**: no graded set, no retry path, no budget, no enforced action boundary.

## Evals & judges
**Design doc first** (one page, before code):

| Decision | States | Becomes |
|---|---|---|
| Success criteria | Gradable output, not "summarize it" | Eval cases |
| Failure handling | Each error retriable or terminal + what the user gets | Error paths |
| Cost & latency budget | Per-request, monthly, latency, reliability floor | Instrumented budget |
| Trust boundary | Who can write inputs; smallest needed access | Data-not-instructions + least privilege |

**Eval loop:**
1. Write cases + expected behaviour **before** the feature.
2. Run and grade. A first score of 2–3/10 is normal.
3. Read the **per-case** breakdown, not just the average.
4. **Change one thing** (prompt, tools or model); keep it only if the score rises.

| Output | Grader | Weak spot |
|---|---|---|
| One correct label/value | **Exact match** (cheap) | Fails valid paraphrase/reordering |
| JSON / code | **Code check** (`json.loads` → 10, error → 0) | Says nothing about content |
| Open-ended quality | **LLM-as-judge** | Noisy, costly; useless until **calibrated** |

- Judge prompt returns strengths, weaknesses, reasoning (≤50 words), then score. **Without reasoning, scores drift to ~6.**
- **Calibrate**: compare judge vs human labels; tighten score meanings and add examples until they agree.
- Run code checks every commit; run the judge as a scheduled pass. Code check suffices → skip the judge.
- **Coverage beats perfection**: 20 cases with edge inputs beat 3 hand-graded ones. Let Claude generate cases from a seed, then spot-check.
- Failure type → fix: formatting → output instructions; wrong facts from retrieved content → retrieval; only long inputs → context handling.
- **Validation checks shape, not the right value.** The eval detects; the prompt fixes.

## Testing & tracing
| Level | Isolates | Misses |
|---|---|---|
| Unit | One function | How parts fit |
| Functional | One Claude call's output shape | The system around it |
| **Integration** | The handoff between two parts | Whole flow |
| End-to-end | Full user flow | **Where** it broke |

- **Silent failures hide at integration seams**: each side passes, the handoff breaks (e.g. `retrieve()` returns dicts, `build_prompt()` expects a string → model answers from memory). Fix the format contract + integration test with real data.
- **Trace** = per-step prompt, tool calls, outputs, timing. Tests say *that* it failed; traces say *which step*.
- **Retrieval router**: cheap classify → `lookup` → fetch once; `multi_step` → agentic search. Only worth it on **mixed** traffic.

## Failure handling
Ask: *would the exact same request plausibly work later?*

| Error | Retry? | How |
|---|---|---|
| `429` rate limit | Yes | Backoff + jitter, honour `retry-after`, cap |
| `529` overloaded (not a rate limit) | Yes | Backoff, then fallback |
| `500`/`502`/`503`/`504`, timeouts | Yes | Backoff; repeated timeouts → fix the request |
| `400`/`401`/`403`/`404` | **No** | Fix input or auth; surface to caller |
| Refusal (HTTP **200**, `stop_reason: refusal`) | **No** | Raise and log |
| Tool error | If transient | Return `tool_result` with `is_error: true` |

- **Unsure → terminal.** Wrongly retrying hammers the service and burns the retry budget.
- The **SDK already retries**; stacking your own loop multiplies attempts. One owner.
- Tight-loop retries deepen a rate limit.
- **Never return an empty result for a failed tool**: the model treats it as real data.

## Model selection
| Tier | Role |
|---|---|
| Fable | Most capable |
| Opus | Above Sonnet's envelope |
| **Sonnet** | Default |
| Haiku | Speed/cost |

- Model sets the cost **baseline**. Start Sonnet; move only on **eval evidence**. Defaulting to the biggest model is the most common costly mistake.
- A higher tier can be cheaper overall if it needs fewer tokens or retries; count the cost of a mistake.
- **Routing**: default model + override on a cheap signal (task type, length). Uniform traffic → pin one. **The eval gates model changes.**

## Cost & orchestration
- Instrument per call from day one: **tokens (in/out), latency, error rate**. Often one step is ~90% of spend.
- Levers: model, prompt/context size, number of tool calls, streaming (perceived speed), batches, caching.
- Streaming tool use: accumulate `partial_json` by index; **never act on a partial `tool_use`**; broken stream → retry the whole request.

**Prompt caching:**
- Write `1.25×` (5 min) or `2×` (1 h); read `0.1×` → pays when reads outnumber writes.
- Automatic (one top-level flag) or explicit `cache_control` breakpoint.
- Needs an **identical prefix** (a timestamp at the top kills it), reuse within TTL, and minimum length.

**Batches**: overnight jobs, backfills, reports; never user-facing. ~50% discount; batching + caching compound.

**Orchestrator-worker**: lead plans → parallel subagents → lead synthesizes.
- ~**15× tokens** of a normal chat; token use explains most of the quality gain.
- Good for independent research; **bad for tightly coupled work like coding**. Capable lead + cheaper workers cuts cost.
- Each subagent needs its own retry/backoff/fallback.

**Reliability floor first** (e.g. answer in 4 s, up to 3 retries), then tune cost above it; a pinned baseline eval enforces it.

## Security
- **Prompt injection**: the model sees one token stream, so instructions inside fetched pages, docs or tool results act as commands. **Treat that content as data.** Trusting your users doesn't help.
- **Jailbreak** attacks the model's own safety rules; **injection** hijacks your app's instructions.
- Delimiters, training and classifiers are soft. **The reliable boundary is what the agent is allowed to do.**

**Defence layers:**
1. Model training + classifiers.
2. Content treated as data.
3. **Least privilege** + locked auth config (whatever edits auth config can act as that identity).
4. **Hooks**: `PreToolUse` returns `permissionDecision: "deny"` with a reason; precedence **deny > ask > allow**; audit everything.
5. **OS sandbox**: filesystem + network isolation; holds when a hook is missing. Reviewers ask about it first.

- Secrets in env vars or a secret manager; a committed secret can't be cleanly rotated.
- Regulated questions: where is data processed (**residency**), how is access logged (**audit**), central control (**managed config**). **ZDR eligibility varies by model and platform**; check the Trust Center.
- **No prompt instruction is a security control.** Hooks must cover every relevant tool and path.

| Threat | Control |
|---|---|
| Prompt injection | Content as data + hook refusing actions driven by untrusted input |
| Jailbreak | Input validation + limited actions |
| Over-broad access | Least privilege, secret manager, locked config |
| Sandbox escape | OS-level file + network isolation |
