Core idea: know token budgets, why output varies, how model choice differs from reasoning, prompting modes, and the ways code reaches Claude.

## LLM behavior
- **Token** = the unit Claude reads, prices and budgets. It is not a word or a character; chars per token depend on the tokenizer and change between model generations.
- **Everything is tokens**: system prompt, history, tool definitions, tool results, documents **and the output**.
- **Context window** = a fixed token budget for **one request**, output included.

**When the window is too small:**
1. Input already bigger than the window → **validation error before generation**.
2. Input fits but generation hits the ceiling → partial output with `stop_reason: model_context_window_exceeded`. **No error is raised.**
3. Neither case silently truncates or expands. **Your app** trims or summarizes history before each call. Dev rarely fills the window; production does.

**Sampling and variation:**
- Each step picks the next token from a probability distribution, so the same prompt can give different, equally correct wording.
- **Temperature**: lower = more repeatable, higher = more varied. **Temperature 0 is still not guaranteed identical.**
- Newest models reject non-default `temperature`, `top_p` or `top_k` with a **400**. Steer with prompting instead.
- Testing: **never assert exact text**. Assert properties (field present, value in range, structure parses). Judge meaning with a model-graded eval.

## Models & reasoning
| Tier | Role |
|---|---|
| **Fable** | Most capable: hardest reasoning, coding, agentic work |
| **Opus** | Demanding work above what Sonnet handles |
| **Sonnet** | **Balanced default** for most production workloads |
| **Haiku** | Speed and cost, within its capability envelope |

- **Start with Sonnet.** Move up to Opus only when an eval shows a quality miss; move down to Haiku only when an eval shows the drop is acceptable.
- **Model choice ≠ reasoning mode.** Reasoning is set **per request**, not per model or per account.
- **Adaptive thinking**: the model decides when and how much to think. Tune depth with **effort**.
- **`budget_tokens` is deprecated** and returns a **400** on the newest models.
- Thinking content is **hidden by default** on the newest models; request summarized display to see it. Some models think adaptively by default, or always.
- Reasoning pays off on hard multi-step problems and is wasted on lookups and classification. Thinking tokens are billed as output.
- Combining levers: capable model + reasoning off = fast and direct. Smaller model + reasoning on = spends tokens thinking. Hardest tasks = capable model + higher effort.

## Prompting modes
| Mode | Prompt contains | Use when |
|---|---|---|
| **Zero-shot** | Instruction only | Simple task, obvious output shape |
| **One-shot** | One input→output example | A structure, casing or edge case the description keeps missing |
| **Few-shot** | Several examples | Same, when one example isn't enough |

- Examples sit in the prompt. They are **not training**; nothing is permanent.
- Each example costs tokens **on every call**. If zero-shot already works, examples only add cost.
- One or two correct examples fix structure faster than more instructions or a higher temperature.
- Examples can let a **cheaper model** pass. Pick the simplest model plus fewest examples that pass the eval.

## Technical substrate
- Claude is an **HTTP REST API**: endpoint + API key + JSON body → JSON response.
- **SDKs** are a thin layer over the same API: auth, request building, **retries**, parsing. Same API, same model.

| Pattern | How | Fits |
|---|---|---|
| **Synchronous** | Wait for the full response | Short responses, backend jobs |
| **Streaming** | Server-sent events on the same connection; client reassembles | Long output, or a user is watching |
| **Async client** | Python `AsyncAnthropic`, `async`/`await`; still real time | Many live calls without blocking |
| **Message Batches** | Submit many requests, get an ID, **poll**; ≤24h, cheaper | Bulk offline work: pipelines, eval runs |

- TypeScript: the standard client is Promise-based; there is no separate async class.
- **Traps:** async client ≠ Batches API. For bulk overnight work a sync loop hits rate limits, and streaming buys nothing when no one is watching.
